# Workflow Alert Automation — Product Requirements Example

> Portfolio / educational case study created to demonstrate Product Management and Product Ownership skills.

## Overview

This project demonstrates how I would define a product capability that allows IT operations teams to automatically process repetitive monitoring alerts.

The goal is to reduce manual operational work while ensuring that important alerts are not missed.

## Problem

IT operations teams receive a large number of repetitive alerts.

Many alerts require the same manual actions:

- Validate the alert
- Identify the affected device
- Create or update a ticket
- Notify the responsible team
- Close or suppress the alert

This creates operational overhead and increases response time.

## Proposed Solution

Introduce a workflow automation capability where users can define:

`Trigger → Conditions → Actions`

Example:

`Machine Offline Alert → Device belongs to Production → Create Service Ticket`

## Target Users

- IT administrators
- MSP operators
- Security operations teams
- Service desk teams

## Expected Outcomes

- Reduce repetitive manual operations
- Improve response time
- Standardize operational processes
- Increase automation adoption
